# Customer Review Sentiment Analysis using NLP and LSTM

## 1. Project Overview and Objective

This project implements a Natural Language Processing (NLP) and deep learning workflow to classify customer/movie reviews as **positive** or **negative**.

Organizations receive large volumes of customer reviews through online platforms. Manually analysing these reviews is time-consuming. The objective of this project is to preprocess review text, convert it into numerical representations, build an LSTM-based sentiment classification model, and evaluate its performance.

This project is completed as **Data Science – Module 5, Assignment 11: NLP Model – Sentiment Analysis using LSTM**.

## 2. Dataset Details

- **Dataset:** IMDB Movie Reviews
- **Source:** Built-in Keras dataset (`tensorflow.keras.datasets.imdb`)
- **Total reviews:** 50,000
- **Training samples:** 25,000
- **Testing samples:** 25,000
- **Vocabulary limit:** 10,000 most frequent words
- **Target variable:**
  - `0` – Negative sentiment
  - `1` – Positive sentiment

The dataset is loaded directly through TensorFlow/Keras:

```python
from tensorflow.keras.datasets import imdb

(X_train, y_train), (X_test, y_test) = imdb.load_data(num_words=10000)
```

The Keras dataset contains integer-encoded reviews. In this notebook, the sequences are decoded into readable text for preprocessing and traditional text representation. The official training and testing partitions are retained.

**No separate dataset download is required.** TensorFlow/Keras downloads and caches the dataset the first time it is loaded.

## 3. Preprocessing Steps

The notebook performs the following preparation steps:

1. **Dataset loading:** Load the IMDB training and testing reviews using Keras.
2. **Text decoding:** Convert the integer-encoded reviews into readable words using the IMDB word index.
3. **Text cleaning:** Convert text to lowercase, remove HTML fragments and non-alphabetic characters, and normalize whitespace.
4. **Stopword removal:** Remove common English stopwords for the traditional Bag of Words and TF-IDF representations. Negation words such as `not`, `no`, and `nor` are preserved because they can change sentiment.
5. **Tokenization and word indexing:** Fit a Keras tokenizer on the training reviews and convert text into integer sequences.
6. **Sequence padding:** Pad or truncate sequences to a fixed length of **200 tokens**.
7. **Train/validation preparation:** Keep the supplied 25,000-review test set separate and reserve 20% of the training partition for validation.

Stemming and lemmatization are optional in the assignment and are not applied in the main LSTM pipeline.

## 4. Text Representation Techniques

The project demonstrates three text representation approaches:

### Bag of Words (BoW)

CountVectorizer represents each review using word occurrence counts. The notebook limits the feature vocabulary to 5,000 features.

### TF-IDF

TfidfVectorizer assigns weights based on the importance of words within a review relative to the training collection. The vectorizer is fitted only on training text.

### Word Embeddings

The LSTM model uses a trainable Keras Embedding layer. It converts each word index into a dense numerical vector that is learned during model training. Unlike BoW and TF-IDF, the embedding-based sequence model retains word order.

## 5. Model Architecture

The sentiment classifier follows the architecture specified in the assignment:

**Input Sequence → Embedding → LSTM → Dense → Sigmoid Output**

Notebook configuration:

| Layer / Setting | Configuration |
|---|---|
| Input | Sequence length: 200 |
| Embedding | Vocabulary size: 10,000; embedding dimension: 128 |
| LSTM | 64 units |
| Dropout | 0.5 |
| Output | Dense layer with 1 unit and sigmoid activation |
| Optimizer | Adam |
| Loss function | Binary cross-entropy |
| Metric during training | Accuracy |

The sigmoid output produces a probability between 0 and 1. A probability of 0.5 or above is classified as positive; a lower probability is classified as negative.

## 9. Performance Analysis

### Impact of sequence length

The model uses a maximum sequence length of 200 tokens. Shorter sequences reduce computation but may omit useful information from long reviews. Longer sequences preserve more context but require additional memory and processing. The notebook examines review-length statistics and the percentage of reviews exceeding the selected limit.

### Importance of the Embedding layer

The Embedding layer maps integer word IDs to trainable dense vectors. These representations are learned for the sentiment classification task and are used by the LSTM to process the review as an ordered sequence.

### Effect of LSTM memory cells

LSTM uses a cell state and input, forget, and output gates to control information flow. These mechanisms help the model retain relevant context and learn dependencies across words in a review.

### Overfitting and possible solutions

Overfitting occurs when a model performs well on training data but generalizes less effectively to unseen data. This notebook uses Dropout and EarlyStopping to help reduce overfitting. Other possible approaches include reducing model complexity, tuning the vocabulary or sequence length, and applying regularization.

### Limitations

- The dataset contains movie reviews, so results may not transfer directly to product, restaurant, or service reviews.
- The Keras dataset is pre-tokenized. Decoding it does not restore all original formatting.
- Sarcasm, mixed opinions, domain-specific language, and subtle context may be difficult to classify.
- The model predicts only positive or negative sentiment and does not include a neutral class.
